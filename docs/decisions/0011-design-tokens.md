# ADR 0011: Дизайн-система — токены цветов, типографики, радиусов, теней и иконки

## Контекст

Нужна была базовая дизайн-система проекта (токены, а не готовые экраны):
цвета, типографическая шкала, шрифт, радиусы, тень и иконки — строго по
прототипу-стайлгайду, полученному от заказчика (`index.html` +
4 SVG-файла: `lock-closed-svgrepo-com.svg`, `lock-open-svgrepo-com.svg`,
`sharp-solid-rabbit-running.svg`, `turtle-animal-icon.svg`; файлы не в
репозитории, только как первоисточник для этой задачи). Прототип — это
статичный HTML-снимок экспорта из инструмента дизайн-прототипирования
(с инжектированным служебным JS/CSS этого инструмента, не относящимся к
самому продукту), а не код проекта — переносить нужно было только
дизайн-решения, не разметку как есть.

## Палитра

| Токен (globals.css) | HEX | Назначение | Где используется |
|---|---|---|---|
| `--palette-warm-gray` → `--background`/`--muted`/`--secondary` | `#F6F5F3` | Фон всех экранов, вдавленные поля | `bg-background` |
| `--palette-deep-green` → `--hero` | `#1E4A40` | Карточки-герои, вход, экран перевыполнения | `bg-hero` |
| `--palette-muted-green` → `--primary` | `#2E6F5E` | Действия, «+», прогресс, состояние «в графике» | `bg-primary` |
| `--palette-ink` → `--foreground`/`--ink` | `#22302C` | Весь текст; прозрачности `.6/.55/.5/.45/.4` — подписи, `.09/.07/.05` — границы/разделители/тень | `text-foreground`, `text-ink-a50` и т.д. |
| `--palette-terracotta` → `--negative`/`--destructive` | `#9A5238` | Отставание, ошибка 500, отрицательная дельта | `bg-negative`, `text-negative` |
| `--palette-mint` → `--positive-hero` | `#8FD4B4` | **Только** поверх `--hero` (глубокий зелёный): часы сверх плана | `text-positive-hero` |
| `--palette-white` → `--card` | `#FFFFFF` | Карточки | `bg-card` |

Соответствие HEX проверено визуально (Playwright-скриншот `/styleguide`) и
по исходному коду — токены объявлены как прямой HEX в `:root`
(`web/src/app/styles/globals.css`), без прохода через `oklch`, поэтому
совпадение точное по построению, а не приближённое конвертацией
цветового пространства.

### Цвета, найденные в прототипе сверх таблицы

- **`#245549`** — встречается как `a:hover{color:#245549}` в служебном CSS
  прототипа. Это hover/pressed-состояние приглушённого зелёного
  (`#2E6F5E`), не самостоятельный цвет палитры. Заведён как производный
  токен `--palette-muted-green-hover` / `--color-accent-hover`, а не как
  отдельная строка палитры.
- **`#B00020`** — встречается в `.sc-logic-error{background:#b00020;...}`.
  Это цвет баннера ошибки самого инструмента предпросмотра прототипа
  (внешний preview-harness, инжектируется в служебный `<style>` в начале
  файла), не часть дизайна продукта. Токеном **не стал** — решение
  сознательное, задокументировано здесь, чтобы не переоткрывать вопрос.

## Типографическая шкала

Источник — таблица «размер / вес / назначение» из задания, сверено с
прототипом:

| Токен (`@theme inline`) | px / вес / трекинг | Назначение |
|---|---|---|
| `text-display` / `font-620` / `tracking-display` | 56 / 620 / −0.04em, `line-height:1` | Главный показатель («2:15») |
| `text-totals` / `font-620` / `tracking-totals` | 44 / 620 / −0.04em, `line-height:1` | Итоги («279:15») |
| `text-screen-title` / `font-640` / `tracking-screen-title` | 34 / 640 / −0.03em | Заголовок экрана |
| `text-day-title` / `font-640` / `tracking-day-title` | 30 / 640 / −0.025em | Заголовок дня («2 июня») |
| `text-list-row` / `font-580` / `tracking-list-row` | 17 / 580 / −0.015em | Строка списка |
| `text-caption` / `font-540` + `text-ink-a50` | 13 / 540 | Пояснение |
| `text-eyebrow` / `font-600` / `tracking-eyebrow` + `uppercase` + `text-ink-a40` | 11 / 600 / 0.12em, UPPERCASE | Надзаголовок секции |

Дополнительно заведён `font-560` (13px/560) — используется в прототипе для
подписей под иконками; в исходную таблицу задания не входит, но встречается
в стайлгайде, поэтому добавлен как ещё один шаг шкалы весов, а не как
магическое число в разметке.

Все числовые значения — через utility-класс `tabular-nums`
(`font-variant-numeric: tabular-nums`, встроен в Tailwind, отдельный
токен не нужен). Часы в интерфейсе — формат `2:15`; в текстах о цели и
отклонении — словами («27 ч 45 мин», «(−9 ч)») — это соглашение
контента, а не CSS-токен, поэтому в токенах не отражено, только здесь.

### Почему системный шрифт, а не Geist

Прототип задаёт `font-family: -apple-system, system-ui, sans-serif` —
никакого кастомного шрифта в дизайне нет. Решение пользователя: убрать
`Geist`/`Geist_Mono` (`next/font/google`) из `root-layout.tsx` и задать
системный стек напрямую через CSS-переменные:

```
--font-sans: -apple-system, system-ui, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
--font-mono: ui-monospace, "SF Mono", "Cascadia Code", "Roboto Mono", Menlo, Consolas, monospace;
```

Следствия: нет сетевого запроса/self-hosted файла шрифта — меньше веса
страницы и нет FOUT/FOIT; шрифт выглядит нативно на каждой ОС (это и есть
цель прототипа — «в манере SF Symbols»); специально проверено, что после
удаления `Geist`/`Geist_Mono` в коде не осталось ссылок на
`--font-geist-mono` (`grep -rn "geist" web/src` — только в комментариях,
поясняющих само решение).

## Почему нет тёмной темы

Решение пользователя: продукт сейчас сознательно light-only. Прототип не
содержит тёмной версии. Чтобы не блокировать тёмную тему в будущем,
класс `.dark` в `globals.css` **оставлен пустым** (а не удалён) с
комментарием, а `@custom-variant dark (&:is(.dark *))` — сохранён. Когда
решение о тёмной теме будет принято, потребуется только заполнить `.dark`
переопределениями семантических токенов из `:root` — структура файла и
разметка (`bg-background`, `text-foreground` и т.д.) менять не придётся,
потому что разметка уже ссылается на семантические токены, а не на
`--palette-*`/HEX напрямую.

## Токены shadcn/ui ↔ палитра проекта

`web/components.json` задаёт `"baseColor": "neutral"` — компоненты shadcn
изначально сгенерированы на нейтральной OKLCH-палитре
(`oklch(...)` серые тона). Все переменные, которые читают примитивы
shadcn (`--background`, `--foreground`, `--card`, `--primary`,
`--secondary`, `--muted`, `--accent`, `--destructive`, `--border`,
`--input`, `--ring`, `--radius`, `--sidebar-*`, `--chart-*`), переписаны в
`:root` на палитру проекта (см. таблицу выше — `--primary` = приглушённый
зелёный, `--destructive` = терракота и т.д.), поэтому компонент вроде
`<Button variant="destructive">` сразу выглядит в стиле приложения без
дополнительных классов. Цветовое пространство — HEX (не `oklch`), чтобы
совпадение с таблицей палитры было точным по построению, а не
приближённым через конвертацию; Tailwind v4 одинаково поддерживает
модификаторы прозрачности (`bg-primary/80` и т.п.) для HEX через
`color-mix()`, так что переход на HEX ничего не ломает.

`--radius` (база для `--radius-sm/md/lg/xl` в исходном шаблоне shadcn)
заменена на прямую шкалу токенов прототипа (см. ниже) — исходная формула
`calc(var(--radius) * k)` не воспроизводила бы набор 12/13/18/20/22/26/28/32
(не арифметическая прогрессия).

## Радиусы и тень

Прототип использует фиксированный, не прогрессивный набор радиусов:
12, 13, 18, 20, 22, 26, 28, 32 (px) и одну тень:
`0 1px 2px rgba(34,48,44,0.05)`. Заведены как:

- `--radius-12` … `--radius-32` (сырые значения) → подключены к
  Tailwind-шкале радиусов `--radius-xs/sm/md/lg/xl/2xl/3xl/4xl` в
  `@theme inline`, поэтому доступны как обычные utility-классы
  (`rounded-xs` … `rounded-4xl`), без произвольных `rounded-[Npx]` в
  разметке;
- `--shadow-card` → `shadow-card` (Tailwind v4 генерирует utility из
  любого ключа `--shadow-*` в теме).
- Нажатие (`transform: scale(0.93–0.98)`) — не токен, а поведенческое
  соглашение (диапазон, не фиксированное число); показано на `/styleguide`
  как рабочий пример (`active:scale-[0.95]`), не как CSS-переменная.

## Иконки

11 иконок вынесены в `web/src/shared/ui/icons/` (один файл — одна
иконка, kebab-case имя файла, PascalCase имя компонента, экспорт через
`index.ts`):

`calendar-icon.tsx`, `month-icon.tsx`, `year-icon.tsx`, `profile-icon.tsx`,
`check-icon.tsx`, `rabbit-icon.tsx`, `turtle-icon.tsx`,
`lock-closed-icon.tsx`, `lock-open-icon.tsx`, `app-mark-icon.tsx`,
`eye-icon.tsx`.

Правила:

- **Единый API пропсов**: `size?: number` (default — как в прототипе для
  каждой иконки: 18 для вкладок/галочки, 16 для замков, 20 для зайца, 22
  для черепахи по ширине — высота считается по соотношению сторон исходного
  viewBox, 24 для знака входа — аналогично, 26 для глаза), `className?`,
  остальные пропсы `<svg>` — через `...props`. Общий тип — внутренний файл
  `icon-props.ts` (не часть публичного API слоя, импортируется только
  соседними файлами иконок).
- **`currentColor` вместо хардкода**: все цвета (`#22302C`,
  `rgba(34,48,44,0.55)`, `#2E6F5E`, `#1E4A40`, `#9A5238`, белый) заменены
  на `currentColor`, цвет задаётся снаружи через Tailwind-класс текста
  (`text-primary`, `text-hero`, `text-negative`, `text-white` и т.п.).
  Единственное исключение — `app-mark-icon.tsx` (знак для входа): в
  прототипе это два уровня непрозрачности одного и того же белого
  (`#fff` / `rgba(255,255,255,0.5)`), не два разных цвета. Заменено на
  `currentColor` + `currentColor` c `fillOpacity="0.5"` для боковых фигур —
  эффект идентичен прототипу при `text-white` на зелёном фоне, но цвет
  остаётся наследуемым, а не зашитым. Настоящих многоцветных (разнородных
  по оттенку) иконок в прототипе нет.
- **Геометрия сохранена 1:1**: viewBox, `stroke-width` (1.5, ушки
  календаря — 1.6), `rx` контейнеров 4.2, `rx` столбиков графика 1.45,
  `r` точек 0.9–0.95, круглые окончания линий (`stroke-linecap="round"`)
  — скопированы из прототипа без изменений.
- **Заяц и черепаха** (`sharp-solid-rabbit-running.svg`,
  `turtle-animal-icon.svg`) прогнаны через `svgo --multipass`:
  заяц 4.07 КБ → ~1.0 КБ (−75.6%), черепаха 6.08 КБ → ~4.7 КБ (−22.8%).
  Проверено визуально (скриншот `/styleguide` рядом с исходным
  прототипом) — геометрия не изменилась, `svgo` только упростил кривые и
  срезал точность координат.

## Демо-страница `/styleguide`

`web/src/pages/styleguide/` (FSD-слайс) + `web/app/styleguide/page.tsx` —
служебная страница для визуальной сверки токенов с прототипом (палитра,
типографика, радиусы+тень, все 11 иконок, кнопки shadcn на новых токенах).
**Не экран приложения** — в навигацию/`BottomNav` не входит. Позже её
можно закрыть за авторизацией/флагом окружения или вовсе удалить, когда
все токены будут проверены в реальных экранах и страница перестанет быть
нужна как эталон сравнения.

## PWA-метаданные

`web/public/manifest.webmanifest`: `name` → «Учёт служения», `short_name`
→ «Служение» (короче, помещается под иконкой на домашнем экране), `lang`
→ `ru`, `background_color` → `#F6F5F3` (тёплый серый — фон всех экранов,
то, что видно на splash-экране до отрисовки), `theme_color` → `#1E4A40`
(глубокий зелёный — фирменный цвет, использован как цвет системной
строки состояния/шапки браузера). `web/src/app/layout/root-layout.tsx`:
`<html lang="en">` → `<html lang="ru">`, `metadata.title`/`description` —
переведены. Иконки 192/512 сгенерированы из знака-логотипа
(`app-mark-icon.tsx`) через `rsvg-convert` — глубоко-зелёный квадрат со
скруглением (`rx=115` при 512×512, что соответствует общей идее радиусов
прототипа) и белым/белым-50% знаком поверх, заменив прежние одноцветные
серые заглушки-placeholder'ы.

## Итоговое правило (зафиксировано также в корневом `CLAUDE.md`)

Цвета, размеры шрифтов, радиусы и тени берутся **только** из токенов
(`@theme inline` / `:root` в `web/src/app/styles/globals.css`) —
utility-классами (`bg-hero`, `text-negative`, `text-display`, `font-620`,
`tracking-eyebrow`, `rounded-2xl`, `shadow-card` и т.д.). Хардкод HEX,
`rgba(34,48,44,...)` или магических px-значений размера шрифта/радиуса
вне `globals.css`, файлов иконок (`shared/ui/icons/`, где `currentColor`
+ геометрия — осознанное исключение) и `/styleguide` (эталон сравнения с
прототипом) — не допускается.
