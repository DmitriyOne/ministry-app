# ADR 0052: CI гоняется только на названных слияниях

Статус: принято, 2026-10-13. Решение владельца.
Меняет триггеры `ci.yml` и `db-test.yml` (ADR 0039 — что эти проверки
проверяют; здесь только о том, когда они запускаются).

## Контекст

До этого `ci.yml` и `db-test.yml` запускались на **каждом** pull request
любой базовой ветки и на каждом push в `develop`/`master`. Ветки в
проекте живут по схеме «фича → релизная ветка → develop → master», и на
нижнем участке этой цепочки проверки гонялись на каждый коммит каждой
фичи — минуты раннера за результат, который всё равно будет перепроверен
выше.

## Решение

Запускать только на тех слияниях, которые владелец назвал:

| База PR | Из какой ветки | Когда |
|---|---|---|
| ветка со словом `release` | любая | **только при открытии** PR (и переоткрытии) |
| `develop` | `release*` | открытие, переоткрытие и **каждый новый коммит** |
| `master` | `develop` | то же |
| всё остальное | — | не запускается |

Условие стоит на job, а не в `on:`: `on:` не умеет задавать разные типы
событий для разных базовых веток, а job, пропущенный по `if:`, раннер не
занимает.

```yaml
if: >-
  github.event_name != 'pull_request'
  || (github.base_ref == 'develop' && startsWith(github.head_ref, 'release'))
  || (github.base_ref == 'master' && github.head_ref == 'develop')
  || (contains(github.base_ref, 'release') && github.event.action != 'synchronize')
```

Имя релизной ветки заранее не известно — известно, что в нём есть слово
`release`, поэтому `contains`, а не точное совпадение.

`workflow_dispatch` добавлен в оба workflow: это способ перезапустить
проверку руками, и правило выше делает его необходимым (см. ниже).

Путевые фильтры `db-test.yml` продолжают работать поверх: фронтовая
правка по-прежнему не поднимает базу.

## Последствия

- **Зелёная галочка на PR в релизную ветку может устареть.** Он
  проверяется один раз, в момент открытия; коммиты, добавленные после,
  не проверяются. Если сделать эти проверки обязательными в branch
  protection, GitHub примет устаревший результат и разрешит слить
  непроверенный код. Это прямое следствие решения, а не недосмотр, —
  запись здесь для того, чтобы при включении branch protection об этом
  вспомнили.
- Черновик (draft) PR тоже даёт событие `opened`. То есть единственная
  проверка PR в релизную ветку сгорает на черновике, и к моменту
  готовности её не будет.
- PR в `develop` не из релизной ветки и PR в `master` не из `develop`
  (например `hotfix/*`) не проверяются вообще.

## Открытые вопросы

Эти четыре решения владелец пока не принимал; записаны, чтобы не
потеряться:

1. Оставить ли `push` в `develop`/`master`. Сейчас оставлен: он проверяет
   **результат** слияния, а не ветку до него, то есть ловит плохой мерж,
   которого в PR видно не было. Цена — один лишний прогон на тот же код.
2. Добавить ли `ready_for_review` в триггеры — тогда PR, открытый
   черновиком, проверится в момент готовности.
3. Делать ли проверки обязательными в branch protection (см. первое
   последствие).
4. Нужен ли прогон для `hotfix/*` → `master`.
