# ADR 0050: требования маршрута — одна типизированная карта

Статус: принято, 2026-10-12.
Заменяет три списка путей, введённые в ADR 0016/0017 (`APP_ROUTES`),
ADR 0045 (списки в `resolveGate`) и ADR 0019/0028 (`APP_SCREEN_PATHS`).
Опирается на ADR 0030 (`routes.ts` — единственное место, где написаны
литералы путей).

## Контекст

На вопрос «чего требует этот адрес» в v2 отвечали три списка, и ни один
не знал про остальные:

| Список | Где | За что отвечал |
|---|---|---|
| `APP_ROUTES` | `web/proxy.ts` | какие адреса проходят щит устройства |
| `SESSION_REQUIRED_PATHS`, `SESSION_FORBIDDEN_PATHS`, `ADMIN_PATHS` | `shared/lib/auth/resolve-gate.ts` | сессия и роль |
| `APP_SCREEN_PATHS` | `features/launch-gate/model/use-launch-gate.ts` | запуск со значка |

Новый экран надо было дописать во все три. И все три **открываются
наружу при ошибке**: адрес, которого в списке нет, не проверяется вовсе,
и ничто об этом не сообщает — ни тип, ни тест, ни линтер.

Это не гипотеза. `/admin/users/new` вышел в `release/v2` отсутствующим в
`APP_SCREEN_PATHS` — единственный экран приложения, который открывался в
обычной вкладке Safari вместо переадресации на `/install`. Нашлось при
написании документации, а не при написании кода и не ревью.

Разбор матчеров middleware, который писали после CVE-2025-29927, называет
этот класс прямо: список исключений никогда не бывает полным, а в большом
приложении маршруты накапливаются быстрее, чем кто-то правит список.

## Варианты

1. **Оставить три списка, добавить тест**, падающий на путь из
   `routes.ts`, не упомянутый ни в одном. Дешево, но тест проверяет
   только то, что путь где-то упомянут, а не то, что упомянут верно; и
   сам тест — четвёртый список.
2. **Одна карта `Record<AppRoute, RoutePolicy>`** (выбрано). Новая запись
   в `routes.ts` **не компилируется**, пока её не классифицировали:
   проверка не в тесте, а в типе, и обойти её можно только вычисляемым
   ключом.
3. **Решать по префиксам в proxy** (`/admin/*` закрыт, остальное
   открыто). Короче, но «открыто по умолчанию» остаётся, а публичная
   часть (`/soon`, `/about`) и так требует поимённого списка.

## Решение

`web/src/shared/config/route-policy.ts`:

```ts
export type RoutePolicy = {
  deviceShield: boolean;                  // классифицирует ли proxy User-Agent
  session: "any" | "required" | "forbidden";
  adminOnly?: true;
  launchGate: boolean;                    // нужен запуск со значка
};

export const ROUTE_POLICY: Record<AppRoute, RoutePolicy> = { ... };
export const resolveRoutePolicy = (pathname: string): RoutePolicy | null => ...;
```

- `proxy.ts`, `resolveGate` и `useLaunchGate` больше не держат списков —
  каждый спрашивает `resolveRoutePolicy`.
- `null` означает «это не наш адрес»: proxy его не трогает, и `/qwerty`
  даёт настоящий 404, а не заглушку устройства (правило ADR 0017
  сохранено).
- **Семейство `/admin` закрыто по префиксу**: экран под `/admin`,
  которого ещё нет в `routes.ts` (динамический сегмент, например
  `/admin/users/[id]`), требует роль `admin` с первого запроса, а не с
  того коммита, где про него вспомнили. Единственное место, где карта
  намеренно отвечает и на неизвестный путь.
- `deviceShield: false` у `/access/*` — не упущение: щит перенаправляет
  именно туда, и включённый щит гонял бы заблокированное устройство по
  кругу. Закреплено тестом.

Инварианты карты (`route-policy.test.ts`), каждый из которых при
нарушении ломает приложение так, что по симптому причину не прочитать:

- у каждого адреса из `routes.ts` есть политика (тип это уже гарантирует,
  но не для вычисляемого ключа);
- у экранов, куда ведёт щит устройства, щит выключен;
- куда гейт отправляет человека, то и принимает его в этом состоянии
  (`/login` без сессии, `/day` с сессией, `/profile` не только для
  админа) — проверяется через `resolveGate`, потому что зацикливается
  именно пара правил;
- у адреса, которому нужна сессия, включён щит устройства;
- публичная часть не требует запуска со значка — иначе до установки
  приложения её не открыть.

## Последствия

- Забыть классифицировать новый маршрут больше нельзя: это ошибка
  компиляции, а не тихо открытый экран.
- Проверено на production-сборке: `/admin`, `/admin/users` и
  `/admin/users/42` теперь отвечают решением гейта, а раньше проходили
  мимо. Там же выяснено про нормализацию пути: `/day/` получает 308 на
  `/day` **до** гейта (содержимое не отдаётся), `/Day` и `/day%2F` — 404.
- Побочное изменение поведения: proxy больше не читает сессию на адресах,
  которым не нужна ни сессия, ни её отсутствие (`/soon`, `/install`,
  `/about`, `/privacy`, `/access/*`). Терять нечего — следующая
  закрытая навигация обновит токен до отрисовки, — а на проекте с
  симметричной подписью это экономит обращение к auth-серверу на каждой
  публичной странице (см. ADR 0044 про `getClaims`).
- Цена: ещё один файл в `shared/config` и косвенность — чтобы узнать,
  чего требует `/profile`, надо открыть карту, а не прочитать условие в
  `proxy.ts`. Это тот же обмен, что в ADR 0030 с `routes.ts`.
