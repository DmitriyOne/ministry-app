# ADR 0056: заголовки безопасности в ответах приложения

## Контекст

Ревью релиза v2 (2026-10-14) показало, что приложение не отдавало **ни
одного** заголовка безопасности: в `next.config.ts` не было `headers()`,
`vercel.json` в репозитории нет вовсе, а `proxy.ts` ставит только cookie
сессии при редиректе.

Для приложения, которое держит сессию в cookie, практическое следствие —
его можно поместить в чужой iframe и показать поверх своей разметки.

## Решение

Один блок `headers()` в `next.config.ts` на `source: "/(.*)"` — то есть
на всё, включая сервис-воркер и статику: заголовок, покрывающий только
страницы, оставляет остальное отвечать как раньше.

| Заголовок | Значение | Зачем |
|---|---|---|
| `X-Content-Type-Options` | `nosniff` | Браузер не угадывает тип по содержимому |
| `X-Frame-Options` | `DENY` | Кликджекинг; оставлен рядом с CSP ради старых WebView, которые знают только его |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Путь внутри приложения не уезжает на чужой домен |
| `Content-Security-Policy` | `frame-ancestors 'none'; base-uri 'self'; form-action 'self'` | См. ниже |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=(), usb=()` | Приложение ничего из этого не просит |
| `Strict-Transport-Security` | `max-age=31536000` | Делает HTTPS свойством приложения, а не площадки |

## Чего здесь намеренно НЕТ

**Полноценного CSP со `script-src`.** Next.js вставляет инлайновые
скрипты начальной загрузки, поэтому настоящая политика требует nonce,
прокинутого через `proxy.ts` на каждый запрос. Ошибка в такой схеме
проявляется белым экраном на чьём-то телефоне и ничем в логах. Три
директивы, которые выбраны, — это та часть CSP, которую нельзя сделать
наполовину: ни одна из них не способна сломать скрипт, который и так
грузился.

`form-action 'self'` здесь не формальность: каждая форма проекта
отправляется в Server Action на том же origin, и более широкого значения
не существует правильного.

**`preload` и `includeSubDomains` у HSTS.** Оба — двери в одну сторону:
запись в preload-список убирается долго, а `includeSubDomains` ломает
любой поддомен, который когда-нибудь будет отдаваться по HTTP. Это
решение владельца домена, а не настройка сборки.

## Последствия

- Проверять заголовки надо на развёрнутом приложении (`curl -I`), а не в
  коде: часть из них (HSTS) Vercel добавляет сам, и после этой правки
  значение может прийти от платформы, а не отсюда.
- Если когда-нибудь понадобится встроить приложение в iframe (витрина,
  демо), `frame-ancestors` и `X-Frame-Options` придётся менять **вместе**
  — иначе старый WebView продолжит запрещать то, что новый уже разрешил.
- Полный CSP остаётся открытым вопросом. Браться за него имеет смысл
  вместе с nonce в `proxy.ts` и проверкой на живом устройстве, а не
  «заодно».
