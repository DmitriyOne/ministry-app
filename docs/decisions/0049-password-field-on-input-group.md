# ADR 0049: `PasswordField` на `@shadcn/input-group`, слайс в `entities`

Статус: принято, 2026-10-06.
Уточняет ADR 0012 (библиотека компонентов) и ADR 0013 (формы и
доступность), следует новому правилу «сначала проверь реестр» из
`CLAUDE.md`.

## Контекст

`PasswordField` был написан руками: поле из `shared/ui/input.tsx`, рядом
нативная кнопка-глазок, своя разметка строки. Порядок поиска компонента в
`CLAUDE.md` требует сначала посмотреть `shared/ui`, потом **shadcn**, и
только затем писать своё — но средний шаг был проверкой по памяти, и его
просто пропустили.

Владелец указал на это и проверил реестр. Там оказался
`@shadcn/input-group` с `InputGroupAddon align="inline-end"` — ровно
шаблон поля с кнопкой внутри, и у него `registryDependencies: button,
input, textarea`, то есть **ни одной новой npm-зависимости**: все три у
нас уже есть.

## Решение

### Компонент собирается на `InputGroup`

`InputGroup` + `InputGroupInput` + `InputGroupAddon align="inline-end"` +
`InputGroupButton`. Своя разметка строки удалена.

`shadcn add` поставить пункт не смог: он спросил про перезапись
`button.tsx` и, не получив подтверждения, вышел, ничего не записав. Это
правильный исход — в нашем `button.tsx` живёт `LinkButton` с клиентской
навигацией (ADR 0024), и его перезапись сломала бы навигацию по всему
приложению. Файл положен вручную из `npx shadcn@latest view`.

### Вендорный файл приведён к решениям проекта

Три правки, каждая — не вкусовая:

1. **Источник состояния ошибки.** Реестр рисует ошибку селектором
   `has-[[data-slot][aria-invalid=true]]:border-destructive`, а фокус —
   `has-[...:focus-visible]:`. Специфичность `has-[...]` выше простого
   класса, поэтому поле с ошибкой в фокусе перекрашивалось бы в цвета
   фокуса, а `aria-invalid` стал бы вторым источником стилей — причём в
   чужом цвете (`--destructive` вместо `--negative`). Заменено на
   `focus-within:` плюс `data-[invalid=true]:`, как требует ADR 0013:
   один источник, `focus-within` раньше в списке, цвета — наши токены.
   Работает это потому, что react-aria `Group` отдаёт
   `data-invalid: isInvalid || undefined` — проверено в исходниках
   пакета: при `false` атрибута нет вовсе, поэтому `data-[invalid=true]`
   точен.
2. **`InputGroupTextarea` удалён** вместе с зависимостью на `textarea`:
   `Textarea` в проекте нет и не нужен, а тянуть его ради неиспользуемого
   экспорта незачем.
3. **`rounded-[calc(var(--radius)-3px)]` заменён на токен `rounded-xs`** —
   произвольные значения в разметке запрещены (ADR 0011).

Плюс обычное приведение к стилю: стрелочные функции, `type` вместо
`interface`, `cn` из `@/shared/lib/cn`, без `import * as React`.

### Слайс переехал в `entities`

`web/src/entities/password-field/`, старый файл в `shared/ui` удалён.

**Это решение владельца, и я с ним не соглашался.** Мой довод: в FSD
`entities` — слой бизнес-сущностей предметной области (человек,
собрание, отчёт), а у поля ввода пароля предметной области нет; граница
`shared/ui` в ADR 0013 описана как «глупая вёрстка с локальным
состоянием самого элемента», и `PasswordField` под неё подходит. Довод
владельца: компонент несёт состояние и логику показа/скрытия, а не
только разметку, и тянет много чего из `shared`.

Решение принято, записано, `steiger` на него не ругается. Практическое
следствие, которое надо помнить: из `shared/ui` этот компонент теперь
недоступен — импорты идут только вниз. Сегодня это никого не задевает,
потребитель один и он выше (экран входа, задача 8).

`FieldCard` остался в `shared/ui`: он действительно чистая вёрстка без
состояния.

## Последствия

- Примитив `input-group.tsx` лежит в `shared/ui` — туда shadcn пишет по
  конфигурации (`components.json`, `aliases.ui`), и менять это ради
  переезда составного компонента не стали.
- Вендорный файл отредактирован, значит следующий `shadcn add
  --overwrite` эти три правки сотрёт. Это общий риск вендорных файлов,
  уже зафиксированный в `CLAUDE.md`; данный ADR — место, по которому их
  можно восстановить.
- Визуально компонент **не проверен**: его пока ничто не отрисовывает.
  Проверять на экране входа (задача 8), в первую очередь отступы, кольцо
  фокуса и кольцо ошибки, а также `pr-1.5`, который `InputGroup`
  добавляет перед addon.
