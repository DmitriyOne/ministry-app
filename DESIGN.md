# DESIGN.md

Справочник по визуальному языку приложения: что из чего собирать, какими
токенами красить, какими отступами дышать.

> **Читать ДО того, как писать разметку.** Любой новый экран, карточка,
> строка списка, форма — сначала сюда. Это не вежливая рекомендация:
> проект дважды платил за то, что компонент писали заново при живом
> готовом (свой тост при существующем `@shadcn/sonner`, своя
> кнопка-глазок при существующем `@shadcn/input-group`). Файл описывает
> **то, что есть в коде**, а не то, как хотелось бы.

Язык файла — русский, как у `CLAUDE.md` и ADR: это рабочая записка о
проекте, а не часть продукта. Сам интерфейс, комментарии в коде и
сообщения коммитов — британский английский (`en-GB`).

Что где лежит: токены — `web/src/app/styles/globals.css`, компоненты —
`web/src/shared/ui/`, обоснования — `docs/decisions/0011-design-tokens.md`
(палитра и типографика) и `0012-component-library.md` (инвентарь).

## 0. Порядок поиска: ничего не изобретать

1. **`shared/ui`** — есть ли готовый компонент проекта. Таблицы ниже.
2. **Реестр shadcn** — если своего нет. **Проверять командой, не
   памятью:**
   ```bash
   npx shadcn@latest search @shadcn -c web -q "<одно слово>"
   npx shadcn@latest view @shadcn/<имя> -c web
   ```
   `-c web` обязателен (иначе падает с `monorepo_root`). Искать по
   **одному** слову: `"input-group"` находит, `"input group field"` —
   нет. `view` показывает зависимости: пункт без новых npm-пакетов почти
   всегда лучше своего кода.
3. **Свой компонент — только после вопроса владельцу.** Не «если первых
   двух не хватило», а «спросить и получить ответ». Решение завести новый
   компонент принимает владелец проекта, не исполнитель: именно так
   появились лишние сущности в прошлом. Получив согласие — писать и
   фиксировать в ADR 0012 и в разделе 6 этого файла.

Экраны **собираются из** компонентов, а не копируют их разметку.
Пиксель-в-пиксель совпадение с макетом не требуется — переиспользование
важнее.

## 1. Цвет

Два слоя. **В разметке использовать только второй.**

### Палитра (сырые значения, в разметке не употреблять)

| Токен | Значение | Как называется |
|---|---|---|
| `--palette-warm-gray` | `#f6f5f3` | тёплый серый — фон экранов |
| `--palette-deep-green` | `#1e4a40` | глубокий зелёный — hero-поверхности |
| `--palette-muted-green` | `#2e6f5e` | приглушённый зелёный — действия |
| `--palette-ink` | `#22302c` | основной текст |
| `--palette-terracotta` | `#9a5238` | ошибка |
| `--palette-mint` | `#8fd4b4` | успех, **только** на зелёном |
| `--palette-white` | `#ffffff` | карточки |
| `--palette-amber` / `-soft` | `#b87912` / `#fff8e8` | подсказка |

### Семантические токены (их и писать)

| Utility-класс | Что значит | Где |
|---|---|---|
| `bg-background` | фон экрана | корень любого экрана |
| `bg-card` | белая карточка | `ListCard`, `Notice`, плашки. **`FieldCard` — не сюда**: у карточки полей фон `bg-background`, чтобы поля читались как врезка |
| `bg-hero` / `text-hero-foreground` | глубокий зелёный и белый на нём | hero-блок `/about`, экран входа, `PaceCard` |
| `bg-primary` / `text-primary` | приглушённый зелёный | кнопка действия, акцент в тексте |
| `text-ink` | основной текст | заголовки, строки списка |
| `text-ink-muted` | пояснение | второй строкой под заголовком |
| `text-ink-faint` | служебное | подписи секций, шевроны |
| `border-ink-a07` | разделитель строк списка | между `ListRow` |
| `border-ink-a09` | разделитель полей | между строками внутри `FieldCard` — ступень темнее, это не опечатка |
| `text-negative` | ошибка на светлом | `Notice tone="negative"` |
| `bg-negative` + `text-negative-foreground` | ошибка **на зелёном** | `InlineError` — залитая плашка, не обводка (29.10.2026) |
| `text-negative-hero` | терракота **на зелёном** | полоса `PaceCard`; для текста ошибки больше не используется |
| `text-positive-hero` | успех **на зелёном** | только поверх `--hero` |

**Две ловушки, которые уже случались:**

- `--positive-hero` (мятный) и `--negative-hero` — **только поверх
  `--hero`**. На светлом фоне они не проходят контраст. Обратное тоже
  верно и стоило `InlineError` его прежнего вида: тинт заводили потому,
  что терракотовый ТЕКСТ на зелёном даёт 1.73:1 — но терракотовая
  ПОВЕРХНОСТЬ этой беды не знает, и белым по ней получается 5.76:1.
- Приглушённого текста ровно **две** ступени, не три и не пять.
  Исходные 0.5/0.45/0.4 из прототипа не проходили WCAG AA; подняты до
  0.72/0.67, а два нижних стали визуально неразличимы и слиты в один
  токен. Не заводить третью «чуть бледнее» — история в ADR 0011.

**Тёмной темы нет** сознательно. `.dark` — пустая заглушка.

## 2. Типографика

Системный шрифт (`--font-sans`), без `next/font`. Шкала именованная:
`text-<роль>`, вес `font-<число>`, трекинг `tracking-<роль>`.

| Класс | Размер / интерлиньяж | Трекинг | Роль |
|---|---|---|---|
| `text-display` | 56 / 1 | `-0.04em` | главное число экрана |
| `text-totals` | 44 / 1 | `-0.04em` | итоги |
| `text-screen-title` | 34 / 1.1 | `-0.03em` | заголовок экрана |
| `text-day-title` | 30 / 1.2 | `-0.025em` | заголовок дня, hero-карточка |
| `text-list-row` | 17 / 1.3 | `-0.015em` | строка списка, кнопка `role-lg` |
| `text-caption` | 13 / 1.5 | — | пояснение, подпись секции |
| `text-eyebrow` | 11 / 1.4 | `0.12em` | надзаголовок (в верхнем регистре) |
| `text-tab` | 10 / 1.2 | `0.01em` | только подписи нижней навигации |
| `text-control` | 16 / 1.45 | — | **поля ввода, не менять** |

Веса: `font-500 520 540 560 580 600 620 640`. Стандартные
`font-medium`/`font-semibold` **не использовать** — в `shared/ui` все веса
идут через один механизм.

**`text-control` — 16px не из эстетики:** iOS Safari зумит вьюпорт, если
поле меньше 16px. Трогать нельзя.

Готовые текстовые роли вместо ручных классов: `Title`, `BodyText`,
`Caption`, `Eyebrow`, `InlineError`, `TextLink`. У `Title` **обязательные
children** — `<Title title={...} />` не соберётся (так уже получился
пустой `<h1>` на `/privacy`).

## 3. Радиусы и тень

| Класс | px | Где |
|---|---|---|
| `rounded-xs` | 12 | плитка иконки в `ListRow` |
| `rounded-sm` | 13 | пилюля роли на `/profile`, кнопки быстрого добавления в карточке часов, чип дня в ленте «Last days» |
| `rounded-md` | 18 | `AppMark` размера 56 и `OfflineScreen` |
| `rounded-lg` | 20 | только вендорные файлы shadcn (`alert`, `input`, `input-group`) |
| `rounded-xl` | 22 | `ListCard`, `FieldCard`, `Notice`, `PaceCard` |
| `rounded-2xl` | 26 | hero-карточка на `/about`, карточка часов на `/day`, карточка ленты «Last days» (тот же радиус, что у карточки часов, — два блока одного экрана) |
| `rounded-3xl` | 28 | не используется нигде |
| `rounded-4xl` | 32 | большая hero-карточка, панель навигации |
| `rounded-button` | 17 | все кнопки ролей |
| `rounded-mark-sm/md/lg` | 14 / 16 / 24 | `AppMark` 44 / 52 / 88 (у размера 56 радиус другой — `rounded-md`) |

Шкала упорядочена **по размеру, не по смыслу**: `rounded-xl` не «больше
подходит карточке», просто 22px. Поэтому радиусы со смыслом (`button`,
`mark-*`) вынесены отдельно.

### Движение

Анимация в проекте — не оформление, а ответ на действие, поэтому
токенов движения ровно два, и оба названы по событию, а не по виду:

| Токен / класс | Что это | Где |
|---|---|---|
| `.pressable` + `--press-scale` | приседание при нажатии, 0.93–0.98 обычно, 0.9 у `HapticButton` и переключателя пароля | кнопки, строки списка, шапка |
| `animate-value-bump` (`--animate-value-bump`) | короткий перескок 1.09 → 1 за 140 мс, когда **число изменилось** | карточка часов на `/day` |

Перескок живёт отдельно от `.pressable` потому, что отвечает на другое
событие: нажатие чувствует палец, а изменение числа видит глаз. 140 мс
выбраны так, чтобы попасть в тот же момент, что системный тик вибрации
(ADR 0040/0060) — разойдись они, и человек прочитает два события вместо
одного. Оба уважают `prefers-reduced-motion`: `.pressable` — правилом в
`globals.css`, перескок — префиксом `motion-safe:` на месте вызова.

Токен `--animate-*` **не** регистрируется в `shared/lib/cn.ts`, в отличие
от размеров/радиусов/теней: проверено тестом, что пакет `cn` разрешает
`animate-*` с любым суффиксом в обе стороны (`cn("animate-value-bump",
"animate-pulse")` → `animate-pulse`) и ни с чем посторонним не
конфликтует. Причина правила — молчаливая подмена группы, а её здесь нет.

Тень в проекте **одна** — `shadow-card` (`0 1px 2px rgba(34,48,44,.05)`).
Плюс три служебные: `shadow-mark-elevated` (`AppMark elevated`),
`shadow-nav`, `shadow-nav-primary` (нижняя панель). Новых не заводить.

## 4. Отступы

Шкала Tailwind по умолчанию (`--spacing` = 0.25rem), дробные шаги
разрешены (`gap-3.5`, `px-5.5`, `pb-5.5`) — прототип их содержит.

Устоявшиеся значения, **брать их, а не придумывать свои**:

| Что | Значение |
|---|---|
| Боковые поля экрана | `px-5` (документные экраны), `px-6` (экраны входа) |
| Вертикальный ритм секций | `gap-4` … `gap-5` |
| Низ экрана | `pb-10` |
| Верх под липкой шапкой | `pt-1.5` |
| Внутри `ListCard` | `px-4`, строка — `py-4` |
| Внутри hero-карточки | `px-5.5 py-6`, колонка `gap-3.5` |
| Между элементами формы | `gap-3.5` (задаёт сам `ActionForm`) |
| Колонка действий | `ActionStack` — `gap-2.5`, ширина `max-w-65` |

### Безопасные зоны и клавиатура — не руками

- **Липкая шапка «назад»**: класс `screen-header-sticky`. Внутри —
  `top: 0` и safe-area **в padding**, никогда `top: env(...)`: при
  `top: env()` остаётся прозрачная щель и текст едет сквозь неё.
- Нелипкая шапка: `pt-screen-header`.
- Якоря внутри `NumberedSection`: `scroll-mt-screen-header` — считается от
  `--screen-header-height`. **Высота шапки и отступ якорей связаны**, и
  эту связь не видят ни `tsc`, ни линтер: вписать 92px руками — значит
  завести шестую копию.
- **Экран с полем ввода — `min-h-app`, не `min-h-dvh`** (ADR 0053). iOS не
  уменьшает layout viewport при открытии клавиатуры, и `100dvh` до и
  после — одно и то же число.
- **Экран внутри route group высоту не назначает вовсе** — её уже
  назначил layout. Второй `min-h-dvh` даёт лишнюю прокрутку ровно на
  высоту панели.
- **Нижняя панель и `Dialog` — `max-h-sheet`, и тело прокручивается
  само.**
  Панель `h-auto`, то есть растёт с содержимым, и панель выбора статуса
  переросла экран: «Save» оказывался ниже видимой области, а прокручивать
  было нечему. Предел высоты — названная утилита, `min-h-0` на
  внутреннем контейнере (иначе флекс-ребёнок не сжимается и предел не
  работает), `overflow-y-auto overscroll-contain` на **теле** панели.
  Ручка и подвал остаются на месте: путь наружу не уезжает вместе с
  содержимым (ADR 0012, обновление 2026-11-02). У `Dialog` то же самое,
  кроме подвала: его кнопки приходят от вызывающего и прокручиваются
  вместе с содержимым.

## 5. Каркас экрана

`CenteredState` — единственный каркас, он же даёт `<main>`.

```tsx
<CenteredState background="warm" | "deep" fill? glyph? actions? footnote?>
```

Правила разметки:

- ровно один `<main>` на экран и ровно один `h1`, уровни не перескакивать;
- `<header>` зарезервирован под навигацию; шапка экрана ставится **рядом**
  с `<main>`, не внутрь, поэтому фон и высота уезжают на обёртку, а
  `CenteredState` получает `fill`;
- декоративные иконки и знаки — `aria-hidden="true"`, если рядом есть
  видимый текст с тем же смыслом.

Типовой документный экран (`/about`, `/privacy`, «Что нового»):

```tsx
<div className="flex min-h-dvh flex-col bg-background">
  <ScreenBackHeader eyebrow={t("eyebrow")} className="screen-header-sticky" />
  <main className="flex flex-1 flex-col gap-4 px-5 pt-1.5 pb-10">
    {/* hero-карточка, затем SectionLabel + ListCard, повторяя */}
  </main>
</div>
```

## 6. Инвентарь `shared/ui`

### Текст и заголовки

| Компонент | Когда |
|---|---|
| `Title` | заголовок; `size` `default`/`compact`, `tone` `ink`/`hero`, `as` для уровня |
| `TextBlock` | пара «заголовок + абзац» (плюс `eyebrow`) — вместо ручной колонки |
| `BodyText`, `Caption`, `Eyebrow` | абзац, подпись, надзаголовок |
| `SectionLabel` | подпись группы над карточкой |
| `TextLink` | тихая ссылка внутри текста |
| `InlineError` | ошибка **на зелёном фоне** — залитая терракотой плашка со знаком |
| `StatusGlyph` | крупный код состояния (404/500) |

### Карточки и списки

| Компонент | Когда |
|---|---|
| `ListCard` + `ListRow` | белая карточка со строками: иконка, заголовок, пояснение, `trailing`, необязательный `href` |
| `PaceCard` | зелёная карточка с заголовком и текстом |
| `FieldCard` + `CardTextField` | карточка полей формы (фон `bg-background`, разделители `ink-a09`) |
| `CardField` | строка карточки полей для нестандартного контрола; `CARD_FIELD_CONTROL_CLASS` — классы самого контрола |
| `PasswordField` | поле пароля с глазком — лежит в `entities/password-field`, **не** в `shared/ui` |
| `Notice` | светлая плашка с иконкой, `tone="positive" \| "negative"` — сообщение внутри формы, с которым человеку надо что-то сделать |
| `FailureCard` | «блок экрана не прочитался»: залитая карточка со знаком, заголовком, строкой и местом под действие (`action`) на заливке `--hero`. Занимает место того блока, который не приехал, и форму экрана не меняет — отступы те же, что у карточки часов (`px-5.5 pt-5.5 pb-4.5`, `gap-4.5`), иначе при отказе экран дёргается. На экране собирается не руками, а через `ScreenLoadFailure` (`features/screen-retry`): он же даёт знак и кнопку «Try again» |
| `Alert` | только через `Notice`, напрямую не собирать |
| `NumberedSection`, `SectionIndex`, `CookieTable` | нумерованный документ (`/privacy`) |

**Чего в этом списке нет и почему.** Карточка ленты «Last days» на
`/day` — белая карточка с сеткой чипсов — собрана в самом экране
(`pages/day/ui/DayLastDays.tsx`), а не взята из `ListCard` и не вынесена
сюда: у неё один потребитель (FSD v2.1 «Pages First»), а `ListCard` —
это «белая карточка с колонкой `ListRow`», и расширять его пропом ради
второй роли значило бы плодить флаги. Повод вынести появится, когда
того же чипа захочет календарь, — и тогда он же скажет, какая нужна
форма (ADR 0065, решение 7).

Там же лежит и ответ на «почему чип — не `LinkButton`»: чип это колонка
из трёх строк без заданной высоты, а `buttonVariants` — одна строка с
фиксированной (`inline-flex items-center`, `h-*`, `px-*`,
`rounded-button`, `bg-card`, `shadow-card`). Клиентскую навигацию
(ADR 0024) там держит `next/link`, нажатие — утилита `pressable`.

### Формы и действия

| Компонент | Когда |
|---|---|
| `ActionForm` | сам `<form>`: `noValidate`, `preventDefault`, `gap-3.5` |
| `SubmitButton` | кнопка отправки: блокировка при ошибках и в полёте, крутилка. Тон и размер — пропами `variant`/`size`, по умолчанию `action`/`role-lg` (ADR 0012, обновление) |
| `Button` / `LinkButton` | роли `deep` `action` `alert` `plain` `heroGhost`, размеры `role` (50) и `role-lg` (54) |
| `ActionStack` | колонка кнопок |
| `PillForm` | форма-пилюля (вайтлист) |
| `InputGroup` + `InputGroupAddon/Button/Text/Input` | поле с кнопкой или подписью внутри рамки (на нём построен `PasswordField`) |
| `Dialog` | подтверждение, и у проекта оно одно на все три (выход, статус служения, закрытие месяца). Нижняя панель, не центрированная коробка: заливка `bg-background` (**не `bg-card`** — на белой панели белая карточка внутри невидима, на этом и попались), радиус 32, заголовок `text-day-title`/`font-640` в `DialogHeader` вместе со строкой под ним, ручка перетаскивания и свайп вниз, предел высоты `max-h-sheet` с прокруткой содержимого. Кнопки даёт вызывающий: тихая слева, ответ справа под пальцем (ADR 0012, обновление 2026-11-02; ADR 0066, решение 11) |
| `Sheet`, `Switch`, `RadioGroup`, `Separator`, `Spinner`, `Input`, `Label`, `Field*` | как в shadcn, с вырезанными кольцами |
| `useSheetDrag` + `SheetDragHandle` + `sheetDragStyle` (`shared/ui/sheet`) | свайп вниз закрывает нижнюю панель (порог 90px) и полоска-ручка над содержимым. Одна реализация на все три — установки, статуса служения и `Dialog`; `showCloseButton={false}` при ней, крестик поверх ручки был бы вторым выходом из панели, которая и так закрывается свайпом, тапом по фону и кнопкой. Рисовать ручку без жеста нельзя: элемент, обещающий отклик, обязан его давать |
| `showToast` / `dismissToast` / `Toaster` (`shared/ui/sonner`) | тост: успех и недоступность бэкенда. Что тостом, а что в форме — ADR 0046 |
| `HoneypotField` | ловушка для ботов в публичной форме |

### Прочее

| Компонент | Когда |
|---|---|
| `AppMark` | знак приложения: `size` 44/52/56/88, `tone` `solid`/`translucent`, `elevated` |
| `ScreenHeader` / `ScreenBackHeader` | шапка с кнопкой «назад» (`features/screen-back`) |
| `ScreenIntro` | `AppMark` над `TextBlock` — шапка экранов входа |
| `CenteredState` | каркас экрана |
| `HapticButton` | кнопка, отвечающая пальцу системным тиком (iOS) — ADR 0040. Берёт `onTap` (один обработчик на палец и на клавиатуру), `radius` под форму кнопки (`full`/`sm`) и всё остальное как `Button`. Отдельный компонент, а не проп у `Button`: оверлей отбирает попадания, и включить его всем кнопкам значило бы сломать драг-жесты панели установки. Нажатие здесь жёстче обычного (0.9 за 75 мс плюс свечение) — силу самого тика выбрать нельзя, поэтому усилено то, что видно |
| `Skeleton` | плашка на месте данных, которых ещё нет. Только в границе загрузки (`loading.tsx`), не как «подождите» вместо работающего экрана — ADR 0055/0059. Тон задаёт вызывающая сторона: `bg-ink-a09` на белой карточке, `bg-white/15` на зелёном (`--hero`, `--primary`) |
| `Progress` | полоса прогресса из реестра (`@shadcn/progress`, вариант `aria-nova`, новых npm-зависимостей не тянет). Дорожка 6px тоном `--ink-a09`, индикатор `--primary`; тон индикатора меняется классом по `[data-slot=progress-indicator]`, а не вторым вариантом компонента. В неё уходят **минуты** с обеих сторон (значение и `maxValue` = часы цели × 60), иначе округлится та самая дробь, ради которой она нужна; перевыполнение не выходит за край — react-aria зажимает значение. Клиентская, поэтому подключается листом: подписи и цифры рядом остаются серверными — ADR 0064 |
| `GoalCard` | зелёная плашка с одним числом: цель месяца и цель служебного года на `/profile`, две рядом в `<dl>` (сам компонент — `<dt>`/`<dd>`). Два тона: `primary` (светлее) и `deep`. Подпись на светлом тоне **белая, а не мятная** — мята на `--primary` даёт 3.5:1 и проваливает AA для 11px, на `--hero` даёт 5.8:1 и проходит. Значение приходит уже словами («30 h» или прочерк): часы и прочерк — дело экрана. Почему не `@shadcn/card` — ADR 0012 |
| `InfoHint` | маленький знак «i» у заголовка блока с цифрами и пузырёк, который он открывает (ADR 0068). Принимает `text` (слова экрана, уже переведённые), `label` (имя знака для чтеца — своё у каждого, иначе на экране три одинаковых) и `surface` — **на чём знак стоит**, а не как он должен выглядеть: `dark` на залитых `--hero` карточках даёт светлый знак и БЕЛЫЙ пузырёк, `light` (по умолчанию) — приглушённый знак и тёмно-зелёный. Один ответ вместо двух, потому что они никогда не были независимы: тёмный пузырёк на тёмной карточке невидим |
| `Popover` | сам пузырёк (`@shadcn/popover`, вариант `aria-nova`, новых npm-зависимостей не тянет). Три числа в нём связаны равенством и меняются только вместе: радиус 12, хвостик 12×6 и `arrowBoundaryOffset={12}` — у знака в конце строки до края пузырька ровно 18px, и хвостику нужно «радиус + половина ширины». `isNonModal` плюс своё закрытие по касанию мимо: по умолчанию popover замораживает страницу, а без модальности react-aria перестаёт закрывать его вовсе. Границу задаёт не окно, а область до `--bottom-nav-space` — иначе пузырёк уезжает под панель меню. Всё измерено в браузере, подробности в ADR 0068 |
| `HeroPill` | короткая подпись **внутри тёмно-зелёного блока**: роль и статус служения на `/profile`. Два тона — `quiet` (мята на `bg-white/10`) и `filled` (тёмно-зелёный текст на мяте); второй для того, что человек пришёл проверить. Назван по месту, а не `Pill`, потому что оба тона построены на мяте, а мята разрешена только на `--hero` (ADR 0011). Подпись на белой карточке — другая вещь и в этот компонент не входит. Почему не `@shadcn/badge` — ADR 0012 |

### Иконки

Собственные компоненты в `shared/ui/icons/`, один файл на иконку, API
`size`/`className`, цвет через `currentColor`. **Не эмодзи и не иконный
шрифт.** Шесть иконок навигации, `/about` и карточки часов — рисунки

`lucide-react` остаётся только для служебных нужд shadcn.

## 7. Чего не делать

- **Не писать HEX, rgba и магические px** в разметке экранов. Исключения
  — сам `globals.css` и файлы иконок.
- **Не возвращать кольца фокуса и ошибки.** Владелец их убрал, и они
  вырезаны **в исходниках** `input.tsx`, `input-group.tsx`,
  `radio-group.tsx`, а не перекрыты сверху. Вендорный файл после
  `shadcn add` — первое место, куда они возвращаются; проверять каждый
  раз.
- **Не объединять классы пакетом `cn` напрямую** — только
  `@/shared/lib/cn`. Пакет не знает наших токенов и молча относит
  `text-list-row` не в ту группу конфликтов (так уже вытеснялся цвет на
  кнопке). **Каждый новый именованный токен в `@theme inline` — сразу в
  соответствующий список в `shared/lib/cn.ts`.**
- **Не смешивать `onClick` с `onPress`** на одном react-aria-компоненте:
  у `Button`/`LinkButton`/`Input`/`Label` — `onPress` и `isDisabled`, а
  не `onClick` и `disabled`. Нативные элементы внутри `shared/ui` —
  обычный `onClick`.
- **Не писать строки в разметке.** Видимый текст и
  `aria-label`/`title`/`alt`/`placeholder` — только через `t("...")`.
  Проверяет `eslint-plugin-i18next`.
- **Не класть сценарий с данными в `shared/ui`.** Можно: локальное
  состояние самого элемента (открыт/показан, `useId`). Нельзя:
  бизнес-сценарии, запросы, доменные схемы, захардкоженные доменные
  тексты.
- **Не убирать кнопку вместе с её местом.** Кнопка, которой на этом
  экране нажать нельзя, остаётся на месте и остаётся видимой: иначе
  заголовок прыгает боком между состояниями, а человек гадает, что было
  в пустоте. Так сделана стрелка «вперёд» в шапке дня: на сегодняшнем дне
  это `Button isDisabled` — приглушённая, но на своём месте (ADR 0063,
  решение владельца 2026-10-27). Прежде её просто не рисовали, а слот
  держал ширину; поменялось потому, что тусклая стрелка сама говорит
  «дальше некуда», а пустое место ничего не говорит. Как именно она
  выглядит выключенной, на месте не пишется — это делает `button.tsx`,
  см. пункт ниже.
- **Не накрывать содержимое, чтобы сказать «идёт сохранение».** Крутилок
  в приложении нет нигде (ADR 0055), а статус блока живёт в правом слоте
  его шапки — там, где карточка часов пишет «5 min steps»: «Saving…» на
  время запроса, «Saved» с галочкой на две секунды, потом обратно.
  Ничего не прыгает, число остаётся на виду, и то же место годится
  следующим блокам (ADR 0062, обновление 2026-10-27).
- **Не писать на месте, как выглядит выключенная кнопка.** Это делает
  `button.tsx`: с 2026-10-28 в базовых классах стоит
  `data-disabled:pointer-events-none data-disabled:opacity-50`, то есть
  выключенная кнопка тускнеет и не ловит касание сама по себе. Зацеп
  именно `data-disabled`, потому что react-aria ставит `aria-disabled`,
  а не нативный `disabled`, и правила `disabled:*` не срабатывают ни на
  одной кнопке приложения (ADR 0012, раздел «Найденный дефект»). Своя
  добавка в `className` нужна только там, где касание принимает не сама
  кнопка, — такое место в проекте одно, оверлей вибрации в
  `HapticButton`.
- **Не делать компонент клиентским целиком** ради одной интерактивной
  части — клиентским должен быть лист.
- **Функции и компоненты — только стрелочные**, пропсы — именованный
  `type` рядом с компонентом. То же относится к файлам из `shadcn add`.

## 8. Перед тем как открыть редактор

1. Этот экран собирается из существующих компонентов? Какие именно?
2. Если нет — искал в реестре shadcn **командой**?
3. Все цвета — токены? все размеры текста — из шкалы?
4. Отступы взяты из раздела 4, а не придуманы?
5. Один `<main>`, один `h1`, иконки `aria-hidden`?
6. Экран внутри route group — высоту **не** назначает?
7. Есть поле ввода — `min-h-app`?
8. Все строки — через словарь?
9. Новый токен — добавлен в `shared/lib/cn.ts`?
10. Новый компонент в `shared/ui` — дописан в ADR 0012 и в раздел 6
    этого файла?

## 9. Как этот файл проверялся и как он сгниёт

Документ, который расходится с кодом, хуже отсутствующего: по нему
пишут, и он врёт уверенно. Поэтому — чем он подтверждён и где слабое
место.

Все таблицы сверены с кодом, а не написаны по памяти: токены вычитаны из
`web/src/app/styles/globals.css`, инвентарь — из `ls shared/ui`, отступы
— подсчётом фактических значений в экранах, размеры кнопок и знака — из
`button.tsx` и `app-mark.tsx`. При первой же сверке нашлись **пять**
собственных ошибок (неверный радиус `AppMark` 56, фон `FieldCard`,
выдуманное применение `rounded-sm`, пропущенные `CardField` и
`InputGroup`) — они исправлены, но сам факт показывает, насколько легко
такой файл наполняется правдоподобным вымыслом.

Повторить проверку:

```bash
# какие радиусы вообще используются и сколько раз
for r in rounded-xs rounded-sm rounded-md rounded-lg rounded-xl \
         rounded-2xl rounded-3xl rounded-4xl rounded-button; do
  printf "%-16s %s\n" "$r" "$(grep -rho "\b$r\b" web/src | wc -l)"
done

# компоненты shared/ui, не упомянутые здесь
for f in web/src/shared/ui/*.tsx; do
  n=$(basename "$f" .tsx)
  grep -qi "$(echo $n | tr -d -)" DESIGN.md || echo "$n"
done
```

**Чего этот файл не делает.** Он не заменяет чтение кода: у компонентов
есть пропсы и комментарии, которых здесь нет, и при расхождении прав
код. Он не дублирует `CLAUDE.md` — там архитектура, доступ, FSD и
процесс, здесь только визуальный язык; если одно и то же начнёт
описываться в обоих, это надо не синхронизировать, а убрать из одного.
И он не описывает экраны — только то, из чего они собираются.
